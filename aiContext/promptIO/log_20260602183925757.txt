## Framework Analysis: ai-test-framework

### Overview

ai-test-framework is a BDD-based Selenium automation framework targeting https://www.demoblaze.com. It is built with:
  - Java 21
  - Selenium WebDriver 4.44.0
  - Cucumber 7.34.3 (BDD layer)
  - TestNG 7.12.0 (execution engine)
  - Maven (build + reporting)
  - Jackson (JSON test data)
  - Masterthought Cucumber Reports (HTML reporting)
  - Log4j 2.26.0 (logging)
  - Commons IO 2.20.0

The framework supports parallel scenario execution via TestNG's DataProvider and generates Masterthought HTML reports after each run.

### File-by-File Analysis

#### src/main/java/assertions/AssertUtils.java
A final utility class wrapping TestNG assertions (assertEquals, assertNotEquals, assertTrue, assertFalse, assertNull, assertNotNull). On failure, it calls Actions.stopTestException() which captures a screenshot and wraps the error in a RuntimeException. This ensures screenshots are always taken on assertion failures. Rule: never use raw TestNG Assert in step definitions.

#### src/main/java/driverConfig/Actions.java
The central Selenium interaction layer. All UI interactions go through here. Key methods:
  - click(By, String) - waits till clickable then clicks
  - type(By, String, String) - clears field then types
  - getText(By, String) - waits till visible then gets text
  - getAlertTextAndAccept() - waits for alert, reads text, accepts it
  - waitTillClickable(By, Duration / String) - WebDriverWait wrapper
  - waitTillNotClickable(By, Duration / String) - negative clickable wait
  - waitTillVisible(By, Duration) - presence of element wait
  - waitUntilTextToDisplay(By, String, Duration / String) - text-in-element wait
  - getWebElement(By) / getWebElements(By) - element finders
  - stopTestException(String, Throwable) - takes screenshot + wraps exception
All waits default to Timeouts.FIVE_SECONDS. Rule: never call driver.findElement() directly in pages or steps.

#### src/main/java/driverConfig/RuntimeConfig.java
Reads browser, executionType, and url from config.properties, with System.getProperty() overrides for CI/CD. This allows config values to be passed as -D Maven arguments.

#### src/main/java/driverConfig/WebDriverFactory.java
Manages ThreadLocal<WebDriver> for thread-safe parallel execution. Methods:
  - createDriver() - branches on executionType (local / browserstack)
  - initializeLocalDriver(String) - supports chrome, firefox, safari
  - setChromeOptions() - disables automation info bar, password manager, autofill
  - getDriver() - returns thread-local driver, throws if null
  - quitDriver() - quits and removes from ThreadLocal
BrowserStack support is stubbed and throws UnsupportedOperationException.

#### src/main/java/enums/Timeouts.java
Enum defining THREE_SECONDS(3s), FIVE_SECONDS(5s), TEN_SECONDS(10s) as Duration values. Used by Actions class. Rule: never hardcode wait durations.

#### src/main/java/hooks/Hooks.java
Cucumber @Before/@After lifecycle hooks:
  - @Before: sets current scenario in ScenarioManager, creates WebDriver via WebDriverFactory, navigates to URL, maximizes window
  - @After: checks pass/fail status, increments ExecutionSummary counters, adds ScenarioResult, removes scenario from ThreadLocal, quits driver
This is the only place driver setup/teardown should happen.

#### src/main/java/utilities/ConfigReader.java
Reads .properties files from the project root. Takes filename (without extension) as constructor argument. Loads file via FileInputStream. Used by RuntimeConfig to read config.properties.

#### src/main/java/utilities/ExecutionSummary.java
Thread-safe execution tracking using AtomicInteger for pass/fail counts and CopyOnWriteArrayList for ScenarioResult objects. Methods: incrementPassed(), incrementFailed(), getPassed(), getFailed(), addResult(), getResults(). Used by Hooks (write) and ExecutionListener (read).

#### src/main/java/utilities/Reporter.java
Single static method log(String message) that attaches plain text to the current Cucumber scenario via ScenarioManager. This makes logs appear inside the Cucumber HTML report. Rule: use Reporter.log() instead of System.out.println() in test code.

#### src/main/java/utilities/ScenarioManager.java
ThreadLocal<Scenario> storage. Methods: setScenario(), getScenario(), removeScenario(). Set in Hooks @Before, accessed by Reporter.log() and Util.attachScreenshot(), removed in Hooks @After. Essential for thread-safe parallel scenario logging.

#### src/main/java/utilities/ScenarioResult.java
Simple POJO holding scenarioName (String) and scenarioStatus (String). Stored in ExecutionSummary and printed by ExecutionListener at the end of the run.

#### src/main/java/utilities/Util.java
Utility methods:
  - isLocalMachine() - reads executionType from config
  - getTimeStamp() - returns yyyyMMddHHmmssSSS formatted string using LocalDateTime
  - attachScreenshot() - takes PNG screenshot via TakesScreenshot and attaches to Cucumber scenario with "Fail_<timestamp>" label

#### src/test/java/runners/Runner.java
The TestNG entry point. Extends AbstractTestNGCucumberTests and overrides scenarios() with @DataProvider(parallel=true) enabling parallel scenario execution. CucumberOptions configure:
  - features: src/test/resources/features
  - glue: web.steps, hooks (step definitions + Cucumber hooks)
  - plugin: pretty (console) + json:target/cucumber/cucumber.json (for reporting)
  - tags: @webSamp (only scenarios tagged @webSamp run)
Has @Listeners(ExecutionListener.class) for pre/post execution callbacks.

#### src/test/java/runners/ExecutionListener.java
Implements TestNG IExecutionListener:
  - onExecutionStart() - prints start banner
  - onExecutionFinish() - prints passed/failed counts + all scenario results, then generates Masterthought HTML report from target/cucumber/cucumber.json into executionReports/Report_<timestamp>/ directory

### Execution Flow (End to End)

1. Maven runs TestNG via maven-surefire-plugin
2. Runner.java picks up all scenarios tagged @webSamp in parallel
3. For each scenario thread:
   a. Hooks @Before: ScenarioManager stores scenario, WebDriverFactory creates ThreadLocal ChromeDriver, navigates to demoblaze URL, maximizes
   b. Steps execute: SignUpPageSteps generates unique user+pass, stores in ContextManager, performs signup, validates alert, then clicks login, signs in with stored credentials, validates navbar username, logs out
   c. Hooks @After: records pass/fail in ExecutionSummary, stores ScenarioResult, removes ThreadLocal scenario, quits driver
4. After all scenarios: ExecutionListener.onExecutionFinish() prints summary, generates Masterthought report into executionReports/Report_<timestamp>/

### Parallel Execution Design

- WebDriver: ThreadLocal in WebDriverFactory - each thread has its own browser
- Scenario: ThreadLocal in ScenarioManager - each thread logs to its own scenario
- Context: ThreadLocal in ContextManager - each thread has isolated username/password
- ExecutionSummary: AtomicInteger + CopyOnWriteArrayList - thread-safe shared counters
- TestDataManager: ConcurrentHashMap cache - thread-safe JSON loading

### Identified Observations / Potential Issues

1. ProductData.java imports io.cucumber.messages.types.Product (wrong import) instead of web.dataManager.pojos.Products. This will cause a runtime error if ProductData is used.
2. cards.json masterCard entry uses "name" key instead of "cardNumber" - Jackson deserialization to Cards POJO will fail for masterCard.
3. ContextManager.removeContext() is never called in Hooks @After - could cause memory leak in long parallel runs (ThreadLocal not cleaned up).
4. BrowserStack support in WebDriverFactory is stubbed and throws UnsupportedOperationException.
5. Address POJO has no no-arg constructor - Jackson deserialization requires either @JsonCreator or a no-arg constructor. Same for Cards and Products POJOs.

### Framework Rules Summary (from famework context.md)

- Never use driver.findElement() in pages/steps → use Actions.*()
- Never use Thread.sleep() → use existing wait methods
- Never hardcode test data → use TestDataManager or wrapper classes
- Never use System.out.println() in test code → use Reporter.log()
- Never create static WebDriver → use WebDriverFactory.getDriver()
- Never share data between steps via static variables → use ContextManager
- Always use AssertUtils for assertions, never raw TestNG Assert
- Every Java file must include @author Ajay Talpur
- Reusable UI sections must become Components, not duplicated in pages
- Step definitions must be thin, calling page methods only
